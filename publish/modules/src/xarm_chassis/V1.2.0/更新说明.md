# V1.2.0 更新说明

## 更新概述

本次更新新增了 `can_listener_trigger.sh` CAN 监听触发器脚本，实现了通过遥控器触发预定义动作的功能。同时修复了固件中的两处关键问题，核心控制逻辑和 CAN 协议保持不变。

## 详细更新内容

### 1. 新增 CAN 监听触发器脚本

**文件**：`chassis_system/can_listener_trigger.sh`

**功能**：监听 CAN 总线上的遥控器信号，根据摇杆位置触发预定义的机器人动作。

**工作原理**：
- 监听 `can2` 接口的 CAN ID 0x051 帧
- 解析数据帧的第 7、8 字节获取摇杆状态
- 根据摇杆组合触发相应的动作文件

### 2. 触发器脚本核心机制

#### 2.1 数据格式解析

脚本解析 CAN 帧数据的第 7、8 字节：

| 字节 | 含义 | 值 |
|------|------|-----|
| 第 7 字节 | 套数（第一摇杆） | 0=上, 1=中, 2=下 |
| 第 8 字节 | 动作（十位）+ 触发（个位） | 动作: 0=上, 1=下；触发: 0=触发, 1=重置 |

#### 2.2 触发规则

- **重置机制**：脚本启动后必须先收到"不触发"信号（第三摇杆向下）才能触发动作
- **冷却时间**：动作执行完成后有 1 秒冷却期，期间忽略触发信号
- **动作互斥**：同一类型的动作不能连续触发（需切换其他动作后才能再次触发）

#### 2.3 动作映射

| 套数 | 动作 | 触发文件 | CAN 接口 |
|------|------|----------|----------|
| 0（上） | 0（上） | Rws.log | can1 |
| 0（上） | 1（下） | Rhs1.log | can1 |
| 1（中） | 0（上） | Rhs2.log | can1 |
| 1（中） | 1（下） | Lax1.log + Rax1.log | can0 + can1 |
| 2（下） | - | 预留（暂无动作） | - |

#### 2.4 执行流程

```
1. 脚本启动 → 等待重置信号
2. 收到重置信号（第三摇杆向下）→ 进入可触发状态
3. 用户选择套数和动作 → 准备触发
4. 第三摇杆向上 → 执行动作（调用 send_data 工具发送 log 文件）
5. 动作执行完成 → 自动进入重置状态，等待下一次重置信号
```

### 3. 新增依赖

**工具**：`send_data`
- **路径**：`../../xarm_action/send_data`
- **用途**：读取 log 文件并通过 CAN 接口发送动作数据
- **参数**：`-f` 指定 log 文件，`-c` 指定 CAN 接口，`-f2`/`-c2` 指定第二组数据（可选）

### 4. 状态管理机制

脚本实现了完善的状态管理：

| 状态变量 | 初始值 | 说明 |
|----------|--------|------|
| `is_running` | 0 | 是否正在执行动作 |
| `need_reset` | 1 | 是否需要重置信号 |
| `last_end_time` | 0 | 上一次动作结束时间 |
| `current_action_name` | "" | 当前准备触发的动作名称 |

### 5. 固件修复

#### 5.1 里程计发送条件修复

**文件**：`mini_car/User/app/chassis_task.c`（第 263 行）

**变更**：

| 版本 | 代码 |
|------|------|
| V1.1.1 | `if (/*last_all_online && (*/now_ms - last_odom_ms >= ODOM_INTERVAL_MS)` |
| V1.2.0 | `if (last_all_online && (now_ms - last_odom_ms >= ODOM_INTERVAL_MS))` |

**修复说明**：
- V1.1.1 版本中 `last_all_online` 条件被注释掉，导致即使遥控器离线也会发送里程计数据
- V1.2.0 版本恢复了该条件判断，确保只有在遥控器在线时才发送里程计数据

#### 5.2 遥控器离线模式修复

**文件**：`mini_car/User/app/controler_task.c`（第 37-40 行）

**变更**：

| 版本 | 代码 |
|------|------|
| V1.1.1 | `if(remoter.rc.ch[7] == 0)` → `ctrl_mode = PROTECT_MODE;` |
| V1.2.0 | `if(remoter.online == 0)` → `ctrl_mode = AUTO_MODE;` |

**修复说明**：
- V1.1.1 版本使用遥控器通道值判断离线状态，判断逻辑不准确
- V1.2.0 版本改为使用 `remoter.online` 标志位判断遥控器在线状态
- 遥控器离线时模式从 `PROTECT_MODE` 变更为 `AUTO_MODE`，允许上位机自动控制

### 6. 兼容性说明

- **向后兼容**：`chassis_control.py` 和 `chassis_listener.py` 无变更
- **CAN 协议**：发送帧（0x050）和接收帧（0x051）格式保持不变
- **固件**：mini_car 固件有两处修复，需重新烧录
